# Independent review contract

1. Select the exact repository/worktree, task requirements, integration base, and candidate. Review the full difference between fixed `BASE` and `CANDIDATE` commits, not a moving branch or just the last commit. For requested uncommitted review, make an isolated snapshot including the intended untracked files and record its digest/manifest; do not create a commit in the user's checkout without authorization.
2. Freeze the candidate during verification/review. Give the reviewer only requirements/acceptance criteria, relevant project policy, worktree path, exact base/candidate or snapshot manifest, and check evidence. Exclude builder conversation and persuasive implementation reasoning.
3. Start a new session for every review round. In the current Codex collaboration surface, use `spawn_agent` with `fork_turns: "none"` and an actually available role. If this interface is absent, inspect the client's supported fresh-session mechanism. Never resume an earlier reviewer to provide independent acceptance of repairs.
4. In PI, core does not expose Codex collaboration tools. A verified delegation extension may provide fresh context; inspect its contract. Otherwise a newly launched PI process can review an isolated snapshot with an explicit brief, `--no-session --no-extensions --no-mcp`, and `--tools read,grep,find,ls` in the installed CLI. A tools allowlist by itself can retain MCP tools; disable those and extensions to keep this fallback read-only. Do not use `--continue`, `--resume`, or `--fork`. Its model configuration may inherit current approved settings. If no independent session can be launched, report the review as pending rather than claim independence.
5. Reviewers stay read-only and return severity, location, observed behavior, evidence, and a correction. Missing/incomplete checks remain explicit. Generic agents are not Bugbot or a separately branded security service.
6. After repairs, invalidate affected evidence and start fresh review of the complete updated change. Preserve valid unaffected work; check dependencies and integrated behavior as required. Recheck source digest/commit and integration base immediately before using a certification.
7. Report the actual stage: implemented, checked, independently reviewed, merged, deployed, verified live. Keep reports outside certified source or recertify added source/report commits. Honor the user's existing release authorization and repository gates.

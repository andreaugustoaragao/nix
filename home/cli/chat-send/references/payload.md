Create payload files privately (`umask 077`). Example:

```json
{"version":1,"operation_id":"followup-20261114-01","blocks":[{"type":"text","text":"Here is the command:"},{"type":"code","language":"sh","text":"pwd\nprintf '%s\\n' hello"}]}
```

`text` blocks contain plain Chat Markdown, `code` blocks preserve their exact text. The optional `language` field is hint metadata only; Chat receives bare code fences because it renders fence language tags as literal code. Code cannot contain triple backticks; supply nonempty blocks with LF line endings. The CLI adds one final plain `- sent by Fulcrum` signature. A standalone signature supplied in a text block is removed before that addition. Signature text inside code is preserved. HTML is never inserted. Formatting must settle to matching displayed text/code before sending; unsupported Markdown or formatting stops.

A send needs a stable `operation_id` in the payload or `--operation ID`. Preview can generate one; use that returned ID when sending the same payload. Optional `mention` is `{"email":"other@example.com","query":"Other"}`, with optional exact `user_id` and `member_id`. Queries contain 2–24 letters/digits. Group routes select a unique matching real chip and verify surrounding content, code, signature, and published chip identity. DM mentions stop before drafting because selection is unreliable. Interrupted or ambiguous chip selection stops without sending.

An optional local attachment is either `"attachments":[{"path":"/absolute/file.pdf"}]` (1 object) or one `--attach PATH` argument, never both. Google Chat's hidden file input accepts one file per message via CDP; multi-file requests are rejected before browser mutation. The path must name a regular file of 1 byte through 25 MiB. The operation snapshots the file once under a private index directory while preserving its basename, then binds index, name, size, and sha256 into the operation fingerprint. A later retry revalidates those bytes and never recopies a changed source over the bound snapshot. Attachment-free payloads and requests omit the `attachments` key entirely.

Routes live in a private JSON file, default `$XDG_CONFIG_HOME/chat-send/routes.json` (or `~/.config/chat-send/routes.json`); use `--routes-file FILE` to select another. Set directory mode 0700 and file mode 0600. No corporate IDs belong in Nix source. Configure an exact title/account label observed in the managed browser, for example:

```json
{"version":1,"routes":{"example":{"url":"https://chat.google.com/app/chat/EXAMPLE","title":"Example Person - Chat","account":"person@example.com","account_label":"Google Account: Example Person (person@example.com)"}}}
```

Routes default to `"kind":"dm"`. Add `"kind":"group"` only for an independently verified group conversation to enable real mention selection. Only canonical Chat conversation URLs are accepted. The command does not discover recipients or guess accounts. Browser profile unavailability returns bounded diagnostics without reconfiguration. Runtime state defaults to `$XDG_STATE_HOME/chat-send` (or `~/.local/state/chat-send`); `--state-dir DIR` allows an isolated location. Payload copies, receipts, and screenshots are private. Stdout contains no message or chat history. Exit codes: 0 preview/sent/cancelled; 2 needs_attention; 3 uncertain; 1 failed. Cancellation is reported as outcome `preview`, reason `cancelled`.

Use `chat-send status --operation ID` to inspect a preview or reconcile an attempted send. It never sends. After the normal publication deadline, send/status may reload the same owned page once only when its composer is still empty and exactly one new matching own message is marked local-only, without visible pending/error markers. Ownership, route, account, draft, and candidate are rechecked first. Confirmation after reload requires the same message ID, exact content, original history anchor, and a server-backed flag. Changed evidence remains uncertain. Raw topic/local-only/pending/error diagnostics stay in the private receipt; hidden message spinners do not count as pending. Retain state after uncertainty: deleting it discards the retry protection. Browser publication evidence has UI-specific limits; the coordinator must validate the DOM probe against the current live UI before enabling a new shape.

When attachments are bound, the sender requires one enabled top-document file input and records the upload attempt before setting its files. Composer chips must then match the bound filenames exactly, with no pending or error state, before preview, focus, or send. Unknown, interrupted, foreign, or unsettled upload state stops without another upload. Cancel removes only those owned settled chips and then clears the owned text. Submission focuses the final plain signature, then traverses controls with at most twelve Tab keys while the attachment chips remain settled. The exact draft, attachments, account, route, enabled Send control, and keyboard focus must still match before one Space activation. A durable attempt marker precedes activation. No pointer Send or alternative activation follows uncertainty. The private action log labels the actual activation as phase `submit`; focus clicks are not submission attempts. Confirmation requires the composer and its attachment chips to be empty and one new own server message whose visible attachment names match the bound names without pending or error markers. The receipt keeps local hashes separate from that UI evidence.
